# mindmap-sync — актуализация карты

Карты `MINDMAP.md` — ментальные карты архитектуры (формат описан в
[references/format.md](references/format.md)); в монорепе их несколько — корневая обзорная
и по одной в каждом подпроекте. Твоя задача — привести их в соответствие с кодом после
завершения фичи, сохранив стабильность карт: разработчик держит их в голове,
и неоправданные переформулировки ломают ментальную модель так же, как устаревшие узлы.

Порог существенности (для самооценки): мерж, завершённая задача, дифф примерно от 10 файлов,
появление или исчезновение модуля — повод обновить карту; правки комментариев и
форматирования — нет.

## Workflow

- [ ]   1. **Найди карты**: `find . -name MINDMAP.md -not -path '*/node_modules/*'`.
       Если карт нет — не создавай их здесь: предложи скилл `mindmap-init` (первичное
       построение) и остановись. В монорепе карт несколько: обрабатывай каждую
       по своей территории (см. шаг 2).

- [ ]   2. **Определи масштаб изменений.**

        Для каждой карты свой якорь и свой скоуп (= каталог, где она лежит; у корневой
        карты монорепы скоуп — состав подпроектов и межпроектные связи):

        ```bash
        git log -1 --format=%H -- <путь к карте>
        git diff --stat <якорь>..HEAD -- <скоуп карты>
        git status --short -- <скоуп карты>
        ```

        В область изменений входят и незакоммиченные правки из `git status`.
        Если git недоступен (не репозиторий) — используй изменения текущей сессии;
        если и они неизвестны, спроси пользователя, что изменилось.

- [ ]   3. **Выбери режим для каждой карты отдельно.**

        **Хирургический** (по умолчанию): изменения затрагивают часть доменов, нет нового
        верхнеуровневого домена, стек прежний.

        **Полная пересборка** — если хоть одно верно:
        - карта ни разу не синхронизировалась и якорь не находится (карта не в git);
        - изменения затронули более ~40% доменов карты;
        - в коде появился новый верхнеуровневый домен/слой или сменился стек;
        - пользователь явно просит пересобрать карту.

- [ ] 4a. **Хирургический режим.** Для каждого затронутого домена:

        - Прочитай изменённые файлы этого домена (по диффу, не весь домен).
        - Обнови только его ветвь карты: добавь новые модули, удали исчезнувшие,
          поправь формулировки сменивших ответственность.
        - Обнови цепочки в «Ключевых потоках», если дифф меняет взаимодействие частей.
        - Обнови «Модели данных» и «Структуру файлов», если дифф меняет модели или состав
          файлов (формат полей и агрегация — `references/format.md`).
        - Узел без подтверждения в коде не удаляй: возможно, это знание человека —
          скрытая интеграция или договорённость (см. Gotchas).
        - **Не трогай узлы незатронутых доменов** — ни формулировками, ни порядком.
        - Монорепа, корневая карта: правь только состав подпроектов и межпроектные
          потоки. Появился новый подпроект без своей карты — добавь узел в корневую
          карту и предложи запустить `mindmap-init` для его полной карты.

- [ ] 4b. **Полная пересборка.** Выполни процедуру построения из скилла `mindmap-init`
      (обследование проекта по `references/format.md`, новый `MINDMAP.md`), с двумя
      отличиями: вопрос про MINDMAP.html и сниппет AGENTS.md **не задаётся** — оба уже
      решены ранее; существующий AGENTS.md не изменяется. Узлы, добавленные человеком
      (не подтверждаются кодом), перенеси в новую карту без изменения формулировок.

- [ ]   5. **Валидация.**

        Для каждой обновлённой карты:

        ```bash
        awk '/^## Структура файлов/{exit} /^(#{1,6} | *- )/{n++} END{print n+0}' <карта>   # семантика: полоса по масштабу проекта (format.md)
        grep -c '</script' <карта>            # должно быть 0
        ```

- [ ]   6. **Пересобери HTML для каждой обновлённой карты, у которой `MINDMAP.html`
       существует** (сниппет запускай в каталоге карты; подставь фактический
       путь к каталогу скилла `mindmap-sync`):

        ```bash
        python3 - <<'EOF'
        import pathlib, re
        skill = pathlib.Path("<путь к каталогу скилла mindmap-sync>")
        t = (skill / "assets/template.html").read_text()
        md = pathlib.Path("MINDMAP.md").read_text()
        fm = re.match(r"^---\n(.*?)\n---", md, re.S)
        mt = fm and re.search(r"^title:\s*(.+)$", fm.group(1), re.M)
        title = mt.group(1).strip() if mt else next(
            l.lstrip("# ").strip() for l in md.splitlines() if l.startswith("# "))
        t = t.replace("__MINDCODE_TITLE__", title)
        t = t.replace("__MINDCODE_MARKDOWN__", md)
        for ph, f in [("__MINDCODE_CSS__", "style.css"), ("__MINDCODE_D3__", "d3.min.js"),
                      ("__MINDCODE_LIB__", "markmap-lib.js"), ("__MINDCODE_VIEW__", "markmap-view.js"),
                      ("__MINDCODE_TOOLBAR__", "markmap-toolbar.js")]:
            t = t.replace(ph, (skill / "assets" / f).read_text())
        pathlib.Path("MINDMAP.html").write_text(t)
        print("MINDMAP.html пересобран")
        EOF
        ```

        Если `MINDMAP.html` не существует — не создавай его. Можно одной строкой упомянуть,
        что офлайн-просмотр собирается скиллом `mindmap-init`.

- [ ]   7. **Отчитайся:** сколько узлов добавлено/удалено/изменено, какие домены затронуты,
       выбран ли хирургический режим или пересборка. Если изменений в коде не было
       (правки комментариев, форматирование) — так и скажи: «карта актуальна», и не трогай файл.

## Gotchas

- **Дифф показывает только то, что видно в коде.** Прежде чем удалять узел, убедись,
  что модуль действительно исчез, а не переехал/переименован.
- **Стабильность формулировок важнее красоты.** Если узел всё ещё верен — не перефразируй его.
- **Вклад человека неприкосновенен: дописанному человеком ВЕРИТЬ.** Узел, который не
  удаётся подтвердить кодом, — не ошибка, а знание человека: скрытые интеграции,
  договорённости, планы. Сохраняй такие узлы с формулировками и местом, вписывай изменения
  кода вокруг; удалять и оспаривать нельзя, при явном устаревании — спроси автора.
  Полная пересборка — только по правилам шага 3.
- **Не добавляй в карту то, чего не проверил:** каждый новый узел должен опираться
  на прочитанный код, а не на правдоподобное предположение из названия файла.
- **Карта — на русском, идентификаторы — как в коде** (см. `references/format.md`).
