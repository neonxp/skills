# mindcode — ментальная карта проекта

Цель: у разработчика, который делает проект целиком с агентским ИИ, должна остаться
ментальная карта кода — как если бы он писал его сам. `MINDMAP.md` — это карта модулей
(не классов и не файлов): домены, ответственность, ключевые потоки данных. Она держится
в голове одним взглядом.

Перед работой прочитай [references/format.md](references/format.md) — стайлгайд карты
с примером. Не создавай карту, не сверившись с ним.

## Workflow

- [ ]   1. Обследуй проект — **выборочно, не читая весь код**:
        - README и docs/: назначение продукта, термины.
        - Манифесты: `go.mod`, `package.json`, `pyproject.toml`, `Cargo.toml`, `pom.xml` —
          стек, зависимости, скрипты сборки.
        - Точки входа: `main.*`, `index.*`, `cmd/`, `app.py` — как запускается система.
        - Каталоги верхнего уровня: что есть что по именам и 1–2 файлам-представителям.
        - Инфраструктура: `docker-compose`, CI-пайплайны, миграции — где живут данные и деплой.
        - Несколько сквозных импортов (`grep` по ключевым пакетам), чтобы понять, кто кого вызывает.

- [ ]   2. Сформируй структуру карты по правилам `references/format.md`:
        - Разделы `##` жёстко заданы шаблоном: «Слои и домены», «Ключевые потоки»,
          «Кросс-функциональное», «Структура файлов» — не переименовывать и не добавлять
          свои верхние разделы.
        - Узел = модуль/подсистема с ответственностью: `internal/orders — жизненный цикл
          заказа`; модели данных — потомки модуля-владельца, поля в формате
          `- имя (тип) — описание`; длинные цепочки потоков — списком шагов.
        - Цель по объёму — по масштабу проекта (таблица в `references/format.md`):
          мелкий 20–40, средний 40–120, крупный 100–150 узлов семантики (без
          «Структуры файлов»). Потолок — не цель: не добивайте объём деталями.

- [ ]   3. Запиши карту(ы): за основу возьми `assets/mindmap-template.md` скилла
       (frontmatter с настройками уже готов). Обычный проект — `MINDMAP.md` в корень;
       монорепа — корневая обзорная + полные карты подпроектов (см. «Монорепа» ниже).

- [ ]   4. Проверь объём и исправь, если нужно:

        ```bash
        awk '/^## Структура файлов/{exit} /^(#{1,6} | *- )/{n++} END{print n+0}' MINDMAP.md
        ```

        Это семантическая часть — «Структура файлов» не считается. Больше 150 — укрупняй
        ветви; меньше 20 у крупного проекта — карта слишком мелкая, загляни глубже в домены.
        Ветка «Структура файлов» лимита не имеет — только правила агрегации из
        `references/format.md`.

- [ ]   5. Задай пользователю **единственный вопрос** (multiSelect, оба пункта предвыбраны):
        - «Создать MINDMAP.html — автономный офлайн-просмотр карты?»
        - «Добавить в AGENTS.md сниппет про автозапуск mindmap-sync?»

        В неинтерактивной среде (задача из пайплайна, нет диалога) — выполни оба и сообщи об этом.

- [ ]   6. Если выбран HTML — собери его из шаблона скилла (подставь фактический путь
       к каталогу скилла `mindcode`):

        ```bash
        python3 - <<'EOF'
        import pathlib, re
        skill = pathlib.Path("<путь к каталогу скилла mindcode>")
        t = (skill / "assets/template.html").read_text()
        md = pathlib.Path("MINDMAP.md").read_text()
        fm = re.match(r"^---\n(.*?)\n---", md, re.S)
        mt = fm and re.search(r"^title:\s*(.+)$", fm.group(1), re.M)
        title = mt.group(1).strip() if mt else next(
            l.lstrip("# ").strip() for l in md.splitlines() if l.startswith("# "))
        t = t.replace("__MINDCODE_TITLE__", title)
        t = t.replace("__MINDCODE_MARKDOWN__", md)
        for ph, f in [("__MINDCODE_CSS__", "style.css"), ("__MINDCODE_D3__", "d3.min.js"),
                      ("__MINDCODE_LIB__", "markmap-lib.js"), ("__MINDCODE_VIEW__", "markmap-view.js"),
                      ("__MINDCODE_TOOLBAR__", "markmap-toolbar.js")]:
            t = t.replace(ph, (skill / "assets" / f).read_text())
        pathlib.Path("MINDMAP.html").write_text(t)
        print("MINDMAP.html готов")
        EOF
        ```

- [ ]   7. Если выбран сниппет — добавь в `AGENTS.md` (создай, если его нет) раздел:

        ```markdown
        ## Ментальная карта кода (mindcode)

        В корне репозитория лежат `MINDMAP.md` — карта архитектуры и знаний о проекте
        (формат markmap: домены, модули, модели данных с полями, ключевые потоки,
        назначение файлов) и `MINDMAP.html` — офлайн-просмотр карты в браузере.

        - После завершения крупной фичи, рефакторинга или миграции запускай скилл
          `mindmap-sync` для актуализации карты — даже если про карту никто не просил.
          Крупная = мерж, завершённая задача, дифф примерно от 10 файлов или
          появление/исчезновение модуля; правки комментариев и форматирования — нет.
        - Карта — источник знаний о проекте: перед задачей загляни в неё — модели данных
          с полями, назначение файлов и потоки сэкономят чтение кода.
        - Планируя изменения, сверяйся с картой: она показывает, где какая ответственность живёт.
        - Не правь `MINDMAP.md` в обход `mindmap-sync`, чтобы карта не разошлась с кодом.
        ```

- [ ]   8. Отчитайся: число узлов, перечень верхних разделов, как смотреть карту
       (открыть `MINDMAP.html` в браузере, либо любой markmap-плагин для `MINDMAP.md`).

## Монорепа

Признак — несколько независимо собираемых/развёртываемых подпроектов (манифесты
в подкаталогах: сервисы, пакеты, приложения). Тогда допустимы вложенные карты:

- Корневая `MINDMAP.md` — обзор: подпроекты как домены верхнего уровня (по узлу
  с ответственностью каждого), межпроектные потоки в «Ключевых потоках», общая
  инфраструктура — в «Кросс-функциональном». Ориентир 15–40 узлов.
- Каждый подпроект получает собственную полную `MINDMAP.md` в своём корне
  (60–150 узлов, обычные правила `references/format.md`).
- Выбор пользователя про HTML (шаг 5) распространяется на все созданные карты;
  сниппет сборки запускай в каталоге соответствующей карты.

## Правила детализации

- Карта ≠ файловый листинг: если узлов больше 150, карта перестаёт умещаться в голову —
  это провал, а не полнота.
- Число узлов — не KPI: карта на 30 честных узлов лучше карты на 80 раздутых; полосу
  задавайте по масштабу проекта (таблица в `references/format.md`).
- Сомневаешься, включать ли модуль? Включи на уровне домена без деталей, sync уточнит.
- Не включай: отдельные файлы, функции, утилиты, сгенерированный код.
- Русские описания, идентификаторы — как в коде.

## Gotchas

- **MINDMAP.md уже существует** — не пересоздавай молча: предложи `mindmap-sync`
  (обновление) или, с явного согласия пользователя, полную пересборку с нуля.
- **Монорепа** — допустимы вложенные карты: корневая обзорная `MINDMAP.md`
    - по одной полной в каждом подпроекте (см. «Монорепа»).
- **В карте не должно быть строки `</script`** (блоки кода запрещены стайлгайдом) —
  иначе сломается сборка HTML.
- **Не читай весь код подряд**: карта строится на выборке (манифесты + entry points +
  по 1–2 файла на домен). Полноту даст `mindmap-sync` по ходу работы над фичами.
- **Карта живёт в корне своего скоупа** (репозитория или подпроекта), а не в docs/ —
  она должна попадаться на глаза так же часто, как README.
