# task-loop — итеративный цикл малых задач

Малая задача — не повод терять дисциплину. Полный sdd здесь избыточен, но три вещи
обязательны до любого действия: сформулированная проблема, простейший подход,
критерий готового. При новых данных они обновляются вслух — смена курса без
проговаривания считается провалом, а не гибкостью.

> **Приоритет правил:** если в корне проекта есть `rules.md`, его инструкции
> превалируют над любыми правилами этого скилла — даже противоречащими им.
>
> **Вопросы пользователю:** если на вопрос возможны варианты ответа — задавай его
> штатным инструментом вопросов с вариантами (в pi — ask_user_question, в других
> агентах — их аналог). Открытый текст — только когда варианты подобрать нельзя.

## Порог

- **Тривиальность** — одно действие, ноль неясностей (опечатка, флаг, ответ на
  вопрос): цикл не нужен, просто сделай.
- **Малая задача** — затрагивает ≤2 файлов, критерий готового формулируется одной
  строкой: этот скилл.
- **Крупнее** — несколько модулей, контракты, неоднозначные требования: sdd,
  начиная с `spec-1-specify`.
- **Разрослась посреди работы** — срезов стало больше трёх или появились
  зависимости/параллельные ветки: переложи остаток в план модуля plan
  (набор plan) и веди исполнение по нему.
- **Шаги `tasks.md` внутри sdd-цикла** — не этот скилл: дисциплину задаёт
  `spec-4-implement`.

## Формулировка до действия

Прежде чем действовать — три строки в чат (не файл, не документ):

    Проблема: <одно предложение, что сломано или что нужно>
    Подход (простейший из возможных): <1–3 предложения; какую альтернативу отвергли и почему>
    Готово, когда: <измеримый наблюдаемый критерий>

- Проблему не сформулировать в одном предложении → задача не маленькая:
  предложи sdd.
- Подход оброс списком шагов больше пяти → то же самое.
- Вводные ясны — показывай формулировку и действуй без ожидания; есть
  неоднозначность — задай вопрос до действия.

## Цикл

- [ ]  1. Сначала взгляд (read-only) — собери контекст из того, что есть:
        - Если в корне есть `MINDMAP.md` — начни с него: домены, модели и потоки
          сэкономят чтение кода (карта от скилла `mindcode`; её наличие не обязательно).
        - Если есть `AGENTS.md` — учти принципы и ограничения проекта.
        - Если есть `rules.md` — учти конвенции процесса (трекер, ревью, «готово»).
        - Иначе изучи затрагиваемый код/систему напрямую — выборочно, не весь проект.
       Потом добери недостающее: не хватает вводных — задай вопросы, не хватает
       фактов — целевые проверки/эксперименты, пока формулировка не соберётся.
       Самое рискованное — первым (fail fast): если центральная гипотеза
       не сработает, лучше узнать это до остальной работы.

- [ ]  2. Вертикальные срезы: один кусок → проверил → работает → следующий. После
       каждого среза система в рабочем состоянии (сборка и тесты зелёные, если они
       есть). Не копи сто строк без прогона проверки.

- [ ]  3. После каждого среза — сверка с «Готово, когда»; каждые 2–3 среза —
       короткая сверка критерия целиком.

- [ ]  4. Новые данные? Итерация вслух: «Обновляю: проблема/подход/критерий теперь
       такие-то» → вернись к формулировке и продолжи. Два поворота подхода → задача
       выросла: предложи sdd или план модуля plan (смотря что соразмерно).

- [ ]  5. Готово: прогони критерий целиком, покажи результат пользователю.

## Границы работы

- Трогай только то, что требует подход. Заметил улучшение в стороне — назови
  пользователю, не чини: это отдельная малая задача, а не расширение текущей.
- «Заодно поправим…» — красный флаг: фиксируй отдельной задачей.

## Красные флаги

- Действие до того, как прозвучали три строки формулировки.
- Молчаливая смена подхода при новых данных.
- Больше 100 строк кода без единой проверки.
- Абстракция до третьего случая использования.
- Один срез «на всё сразу» вместо последовательности проверяемых кусков.
- Несколько несвязанных правок в одном коммите: откатить можно только всё сразу.

## Gotchas

- **Формулировка ради галочки** — «Проблема: починить баг» не формулировка;
  в одном предложении должно быть понятно, что наблюдается и где.
- **Критерий «работает»** — не критерий; нужен наблюдаемый результат
  («команда X проходит», «страница отдаёт 200 за <300 мс»).
- **Скилл на тривиальщине** — требование трёх строк к правке опечатки убивает
  доверие к циклу; порог — часть дисциплины.
- **Два поворота — сигнал** — не третий и не пятый: после второго разворота
  честно скажи, что задача не маленькая.
